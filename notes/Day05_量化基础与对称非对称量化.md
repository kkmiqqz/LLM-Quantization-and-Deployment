# Day 5: 量化基础与对称/非对称量化原理

## 一、 核心概念：什么是量化？

**量化（Quantization）**，本质上是一种**有损压缩**技术。它把大模型中原先占用空间大、精度高的浮点数（如 FP16，占 2 字节），映射到占用空间小、精度低的整数（如 INT8，占 1 字节；或 INT4，占 0.5 字节）。
通过这种方式，模型体积缩小 2~4 倍，推理速度大幅提升，是端侧部署的绝对核心。

### 1.1 位宽 (Bit) 与字节 (Byte)
*   **FP16 (16-bit)**：1 个参数占 2 个字节。
*   **INT8 (8-bit)**：1 个参数占 1 个字节，范围 `[-128, 127]`。
*   **INT4 (4-bit)**：1 个参数占 0.5 个字节，范围 `[-8, 7]`。（注：工程中对称量化通常舍弃 -8，只用到 `[-7, 7]` 以保证正负对称）。

### 1.2 量化与反量化公式
*   **量化**：`整数 = round(浮点数 / Scale) + Zero-point`
*   **反量化**：`浮点数 ≈ (整数 - Zero-point) * Scale`
（其中 `Scale` 是缩放因子，`Zero-point` 是零点偏移量）

## 二、 对称量化 (Symmetric Quantization)

**核心思想**：以 **0** 为中心，正负两边一视同仁，使用相同的缩放比例。

**公式推导**：
*   `Scale = max(abs(w)) / 127`（对于 INT8）
*   **没有零点 (Zero-point = 0)**。

**通俗举例**：
假设我们的数据范围是 `[-3.0, 2.0]`。
因为是对称的，我们只看绝对值的最大值，即 `3.0`。
*   `Scale = 3.0 / 127 ≈ 0.0236`。
*   原数据 `-3.0` 映射到 `-127`。
*   原数据 `2.0` 映射到 `round(2.0 / 0.0236) = 85`。

**痛点（浪费格子）**：
因为是对称的，负半轴用到了 `-127`，正半轴为了对齐，只能用掉 `85` 左右，正数区间的 `85` 到 `127` 这个范围的格子被白白浪费了。
**为什么权重（Weights）喜欢用它？** 因为大模型的权重往往服从均值为 0 的正态分布，且没有零点偏移，GPU 硬件计算矩阵乘法时速度极快。

---

## 三、 非对称量化 (Asymmetric Quantization)

**核心思想**：以 **实际数据的最大最小值** 为边界，引入一个 **零点（Zero-point）** 来平移坐标系，让 INT8 的所有格子完美套住浮点数的 `min` 到 `max`。

**公式推导**：
*   `Scale = (max - min) / 255`（对于 INT8 的 256 个格子）
*   `Zero-point = round(-min / Scale) - 128`

**通俗举例**：
假设激活值范围是 `[-2.0, 5.0]`。
1. 跨度是 `7.0`，`Scale = 7.0 / 255 ≈ 0.02745`。
2. 找零点：最小值 `-2.0` 对应 INT8 的 `-128`。从 `-2.0` 走到 `0.0`，跨越了 `2.0`，需要占用 `2.0 / 0.02745 ≈ 73` 个格子。
3. 所以浮点数的 `0.0` 对应的 `Zero-point = -128 + 73 = -55`。
4. 这样，负数占用了 `[-128, -55]`，正数占用了 `[-55, 127]`。**完美利用了每一个格子，没有浪费。**

**痛点（计算慢）**：因为引入了 `Zero-point`，硬件在计算矩阵乘法时，每次都要做额外的减法运算，增加了计算开销。

## 四、 实验分析：离群值（Outlier）的毁灭性打击

在 `day05_toy_quant.py` 中，我们手动实现了一个对称量化器，并对比了两组数据的量化误差。

### 实验数据 1：正常情况
原始数据：`[-1.0, -0.4, 0, 0.3, 0.9]`
*   最大绝对值 = 0.9，Scale = 0.9 / 127 ≈ 0.007874
*   量化后的整数数组：`[-127, -51, 0, 38, 114]`
*   反量化后的浮点数组：`[-1.0, -0.4015, 0, 0.2992, 0.8976]`
*   **平均绝对误差 (MAE)**：`0.000945`（非常小，精度保留极好）

### 实验数据 2：加入离群值
原始数据：`[-1.0, -0.4, 0, 0.3, 10.0]` (加入了一个极大的正数 10.0)
*   最大绝对值变为 10.0，Scale = 10.0 / 127 ≈ 0.07874
*   量化后的整数数组：`[-13, -5, 0, 4, 127]`
*   反量化后的浮点数组：`[-1.0236, -0.3937, 0, 0.3149, 10.0]`
*   **最大绝对误差 (Max Absolute Error)**：`0.0236`，相比正常情况放大了 20 多倍！

### 深度解析：为什么误差会爆炸？
因为为了容下那个极端的 `10.0`，`Scale` 被迫从 0.0078 撑大到了 0.078。原来原本正常的 `-1.0`，除以 0.078 之后，只能变成 `-13`。在整数格子里，它和 `0` 只差了 13 格，这意味着原本带有丰富信息的负数区间的精度被彻底“压扁”了。

> **工程解决方案**：在大模型量化中，我们绝不会让整个模型共用一个 `Scale`，而是引入 **分组量化 (Group-wise Quantization)**。例如每 128 个权重分为一组，各自计算各自的 `Scale`。这样即便某一组出现了一个离群值，也不会影响其他组。这就是 AWQ 等高级算法的底层地基。

## 五、 重点问题

1.  **对称量化和非对称量化有什么区别？各自适用什么场景？**
    答：对称量化以0为中心，无零点偏移，计算极快，适合处理呈正态分布的权重（Weights）；非对称量化引入 Zero-point 平移，能完美利用格子处理偏移数据，精度更高但计算略慢，适合处理激活值（Activations）。
2.  **为什么大模型量化常使用 W4A16 这种混合精度？**
    答：模型权重（W）参数量极大，是显存占用的绝对大头，通常用 INT4 极致压缩体积；而激活值（A）是在推理时动态产生的中间结果，对精度极其敏感，所以保留 FP16 以维持模型智商。
3.  **什么是量化中的离群点（Outlier）？怎么解决？**
    答：离群点是指数值极大或极小的少数数据。它们会撑大全局量化的 Scale，导致其他正常数据精度严重受损。工程上通常采用分组量化（Group-wise）、或者 AWQ 等算法来保护重要权重、处理离群点。
